# novel-retro

> 校准循环的反馈环节：用**真实数据**对比预测，找出偏差、归因、提取观察。
>
> 不复盘的预测等于占星。没有数据的复盘等于写感想。

---

## 前置条件

1. `.novel-state.json` 存在且 `pending_retros` 列表非空（或用户指定了具体作品）
2. 对应的预测文件存在于 `predictions/` 目录下
3. **复盘窗口已过**：
   - 短篇/中短篇：发布后 ≥ 7 天
   - 连载小说（中篇/长篇/超长篇）：发布后 ≥ 30 天
4. 用户能提供真实平台数据（不是"感觉"）

---

## 执行流程（6 阶段）

### Phase 0 — Locate Prediction（定位预测文件）

1. 如果用户指定了作品名 → 在 `predictions/` 下搜索匹配文件
2. 如果未指定 → 读取 `.novel-state.json` 的 `pending_retros[0]`（FIFO）
3. 读取预测文件全文
4. **完整性校验**：计算 `## 预测` 段的内容 hash（SHA-256 前 12 位），记录在变量中用于 Phase 5 比对
5. 如果预测文件有 `_redo.md` 版本 → 以最新的 `_redo.md` 为准

**找不到预测文件** → 报错并提示用户先跑 `/novel-predict`。

---

### Phase 1 — Collect Data（收集实际数据）

向用户逐项收集以下数据（必填项标 *）：

| 数据项 | 必填 | 说明 |
|--------|------|------|
| 签约状态 | * | 通过 / 拒绝 / 待审 |
| 收藏数 | * | 当前总收藏（或指定时间节点的快照） |
| 阅读量 | * | 总阅读量或千次阅读收益的分母 |
| 收入 | * | 人民币金额（或"0"/"尚未结算"） |
| 追更率 | | 如平台提供 |
| 完读率 | | 如平台提供 |
| 编辑反馈 | | 签约反馈原文或概要 |
| 读者评论概要 | | 高频关键词或典型评论 |
| 平台推荐情况 | | 是否进推荐位 / 曝光量 |

**收集规则**：
- 用户说"还没数据" → 终止复盘，告知等待窗口
- 用户只给"感觉不错" → **拒绝**，要求具体数字
- 用户给了部分数据 → 接受并标注哪些字段缺失

---

### Phase 2 — Compare（对比）

构建对比表，逐项列出预测值 vs 实际值：

```markdown
| 指标 | 预测 | 实际 | 偏差方向 | 偏差幅度 |
|------|------|------|----------|----------|
| 签约 | yes | yes | - | 命中 |
| 收藏 | 500-1200 | 890 | - | 区间内 |
| 收入档位 | B(500-2000) | ¥1,350 | - | 命中 |
| ... | | | | |
```

**偏差方向编码**：
- `命中` — 在预测区间内
- `偏高` — 预测高于实际（乐观偏差）
- `偏低` — 预测低于实际（悲观偏差）
- `方向错误` — 预测 yes 实际 no（或反之）

---

### Phase 3 — Attribution（归因分析）

回顾 Phase 2 中推理因素表的 9 个维度，逐一判断：

**对每个维度回答**：
1. 该维度的打分方向是否正确？
2. 如果错误，是什么导致了误判？（信息缺失 / 权重不对 / 判断标准有误）
3. 如果正确，是真的看对了还是碰巧对了？

**归因分类**：
- **判断正确** — 理由也正确，可信
- **判断正确但理由错误** — 碰巧，不可复用
- **判断错误 + 信息缺失** — 当时不可能知道的信息导致
- **判断错误 + 权重偏差** — 高估/低估了某因素的影响力
- **判断错误 + 标准偏差** — 评分标准本身需要修正

---

### Phase 4 — Extract Observations（提取观察）

从归因分析中提取 **0-2 条** 可复用的规律假说。

**提取标准**：
- 必须是可操作的（能转化为具体的打分调整）
- 必须有本次复盘的具体数据支撑
- 不是"下次要写好一点"这种废话

**写入位置**：追加到 `rubric_notes.md` 的 `## 观察区`

**格式**（遵循 [shared-references/observation-lifecycle.md](../../shared-references/observation-lifecycle.md)）：

```markdown
### [观察标题]
- 描述：一句话概括规律
- 首次发现：YYYY-MM-DD，来自《作品名》复盘
- 支持证据：
  - YYYY-MM-DD《作品名》：具体数据佐证
- 反对证据：
  - （暂无）
- 验证次数：1/3
```

**如果是已有观察的重复验证**：
- 不新建条目，而是在已有观察的"支持证据"下追加一条
- 更新"验证次数"

**如果本次无新观察**（偏差太小或无法归纳）：
- 不强行编造观察
- 在复盘段注明"本次无新观察提取"

---

### Phase 5 — Write Retro（写入复盘）

1. **编辑预测文件**：使用 Edit 工具，将结构化复盘内容追加到 `## 复盘` 段（替换原有的占位文本 `（待填 — 发布后 T+N 天跑 /retro）`）

   复盘段格式：
   ```markdown
   ## 复盘

   **复盘时间**: YYYY-MM-DD
   **实际数据采集日**: YYYY-MM-DD（发布后第 N 天）
   **数据完整度**: 完整 / 部分缺失（缺 XXX）

   ### 对比表

   | 指标 | 预测 | 实际 | 偏差方向 | 偏差幅度 |
   |------|------|------|----------|----------|
   | ... | | | | |

   ### 归因分析

   | 维度 | 打分 | 判断 | 归因类型 | 说明 |
   |------|------|------|----------|------|
   | ... | | | | |

   ### 关键发现

   - {1-3 条最重要的发现}

   ### 提取观察

   - {已写入 rubric_notes.md 的观察标题} / 无新观察
   ```

2. **验证预测段完整性**：重新计算 `## 预测` 段 hash，与 Phase 0 记录的 hash 比对。**不一致 → 报错终止**（说明有人在复盘过程中修改了预测段，违反 immutability 原则）。

3. **更新 .novel-state.json**（Read-Modify-Write 原子操作）：
   ```jsonc
   {
     "calibration_samples": N + 1,        // +1
     "last_retro_at": "当前 ISO 8601 时间",
     "pending_retros": [...移除当前作品]    // 从列表中删除
   }
   ```

4. **检查连续方向性错误**：
   - 读取最近 N 份有复盘的预测文件
   - 统计连续偏差方向（连续偏高 or 连续偏低）
   - 如果 `consecutive_directional_errors >= 3` 且方向相同 → 输出建议：
     > 连续 {N} 次预测偏{高/低}，建议跑 `/novel-bump` 检查是否需要调整 rubric 权重。

5. **输出总结**：
   > 复盘完成。校准样本数：{N}。
   > - 本次偏差方向：{偏高/偏低/命中}
   > - 新增观察：{N} 条（已写入 rubric_notes.md）
   > - 下一步：继续创作下一部作品，积累校准样本。

## Refusals（必须拒绝的场景）

| 场景 | 拒绝理由 | 回复模板 |
|------|----------|----------|
| 没有真实数据就要复盘 | 违反原则 #2 | "复盘不是写感想。请提供具体的收藏数/阅读量/收入数据。" |
| 复盘窗口未到 | 数据不稳定 | "距离发布仅 {N} 天，短篇需满 7 天、连载需满 30 天。请 {日期} 后再来。" |
| 找不到预测文件 | 无对照基准 | "未找到对应预测文件。请先跑 `/novel-predict` 建立预测基线。" |
| 用户说"帮我感觉一下" | 模糊数据无法校准 | "需要可验证的数据点。'感觉'是校准循环之前的状态。" |
| 用户想修改已有复盘 | 复盘也应保持稳定 | "已有复盘不建议修改。如有新数据，可追加到复盘段末尾。" |

## 边界情况

### 部分数据复盘

用户只有部分数据（如知道签约结果但不知道具体收入）：
- 接受已有数据，对比表中缺失项标注"数据缺失"
- 在 header 标注 `数据完整度: 部分缺失（缺 XXX）`
- `calibration_samples` 仍然 +1（部分数据也是数据）

### 连载小说多次复盘

连载小说可能有多个复盘时间点（如 T+30d、T+90d、T+180d）：
- 第一次复盘正常写入 `## 复盘` 段
- 后续复盘追加为 `## 复盘 (T+{N}d)` 子段
- `calibration_samples` 只在第一次复盘时 +1

### 预测被标记为 non_blind

non_blind 预测的复盘：
- 正常执行所有步骤
- 但归因分析中额外标注"本次预测为 non_blind，归因可信度降低"
- `calibration_samples` 仍然 +1（non_blind 也有学习价值，但 bump 时权重降低）

## 与其他模块的关系

| 模块 | 关系 |
|------|------|
| `/novel-predict` | 上游——复盘以预测为对照基准 |
| `/novel-publish` | 上游——发布登记确认复盘窗口起点 |
| `/novel-bump` | 下游——连续方向性错误时建议 bump |
| `rubric_notes.md` | 写入目标——观察追加到观察区 |
| `observation-lifecycle.md` | 规范——观察格式与晋升规则 |
| `hooks/prediction-immutability.sh` | 约束——复盘不得触碰 `## 预测` 段 |

## 复盘窗口参考

| 品类 | 最短窗口 | 建议窗口 | 说明 |
|------|----------|----------|------|
| 超短篇（0.8-2.5万） | 7 天 | 7-14 天 | 完本签约，数据沉淀快 |
| 中短篇（2.5-8万） | 7 天 | 7-14 天 | 完本签约，数据沉淀快 |
| 中篇（3-15万） | 30 天 | 30-60 天 | 连载模式，需等推荐周期 |
| 长篇（15-50万） | 30 天 | 60-90 天 | 多轮推荐，数据波动大 |
| 超长篇（50-200万） | 30 天 | 90-180 天 | 长尾效应明显 |
