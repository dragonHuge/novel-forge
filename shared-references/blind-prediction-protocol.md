# 盲预测协议（Blind Prediction Protocol）

> 校准闭环的核心不变量：预测时不得接触任何已发生的表现数据。

---

## 什么是"盲"

"盲"指预测者在写下预测时，**尚未看到该作品发布后的任何表现数据**。
这一约束确保预测反映的是对内容质量的判断，而非对已知结果的后见之明。

预测一旦写下，由 `prediction-immutability` hook 强制保护，任何 Agent 或人工均无法修改 `## 预测` 段的内容。

---

## 什么会打破"盲"（禁止在预测前查看）

以下数据一旦被预测者在预测写入前看到，即视为"盲"被打破，预测作废：

- 收藏数 / 追更数
- 阅读量 / 完读率
- 收入金额 / 千次阅读收益
- 评论内容与数量
- 签约结果（通过 / 拒绝 / 具体反馈）
- 平台推荐数据（曝光量、点击率）
- 排名信息（分类榜、飙升榜等）

---

## 什么不打破"盲"（预测时可以参考）

以下信息属于先验知识，不会打破盲条件：

- **其他作者的公开数据**：同题材爆款分析、市场基准线
- **历史相似作品**：自己过往同类型作品的发布后数据（用于建立 baseline）
- **发布前的草稿内容**：作品本身的全文、大纲、创作设定
- **平台规则与趋势**：签约标准、推荐算法特征、热门题材分析
- **立项评分结果**：立项评分是预测的前置输入，不是后验数据
- **第三方审阅意见**：beta reader 反馈、AI 质量审核结论

---

## 预测文件命名

```
predictions/YYYY-MM-DD_《书名》.md
```

示例：
```
predictions/2026-05-19_《末世囤货：全球崩坏我无敌》.md
predictions/2026-06-01_《规则怪谈：我在恐怖游戏里开挂》.md
```

日期为预测写入日（非发布日）。一部作品只对应一份预测文件。

---

## 重做预测（_redo.md 工作流）

当出现以下**合法情况**需要重做预测时：

1. **创作设定发生重大变更**：如完全推翻大纲重写、更换核心题材
2. **发现预测时的事实错误**：如误判了平台规则、基准线引用错误
3. **作品形态根本改变**：如从短故事改为长篇连载

重做流程：

```
1. 原预测文件保持不动（hook 强制保护）
2. 创建新文件：predictions/YYYY-MM-DD_《书名》_redo.md
3. 在新文件的 header 中注明：
   - redo_reason: 重做原因
   - original_file: 指向原预测文件路径
4. 正常写入新的 ## 预测 段
5. 复盘时以最新的 _redo.md 为准，但原文件留作审计轨迹
```

**不合法的重做理由**（会被拒绝）：

- "预测写低了，想改高一点" → 不允许
- "看到早期数据不好，想调低" → 已经打破盲，整个预测作废
- "觉得写得不够详细" → 在 `## 复盘` 段补充，不重做

---

## 与 hook 的关系

| Hook | 保护对象 | 拦截行为 |
|------|----------|----------|
| `prediction-immutability.sh` | `predictions/*.md` 中 `## 预测` 段 | Edit/Write 触及已有内容 |
| `score-immutability.sh` | `创作设定.md` 中 `## 立项评分` 段 | Edit/Write 触及已有内容 |

两个 hook 共用同一个绕过环境变量 `NOVEL_BYPASS_IMMUTABILITY=1`，仅限纯格式修正（如修复 Markdown 渲染问题），语义变更禁止绕过。

---

## 设计哲学

盲预测的价值不在于"猜对"，而在于：

1. **迫使创作者在发布前认真思考**作品的市场定位与质量水平
2. **积累校准样本**以改进评分维度和权重
3. **消除后见之明偏差**让复盘真正有信息增量
4. **形成正向反馈循环**预测越准 → 对质量的判断越可靠 → 创作决策越好
